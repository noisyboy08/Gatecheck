THE AGENT

What actually did the research

A Python pipeline, not a spreadsheet filled in by hand. Source in /agent.

01

Composio catalog cross-check

For each app, query the Composio SDK / toolkit directory (composio.dev/toolkits/<slug>) for an existing managed toolkit — the strongest possible "buildable today" signal, since it means the auth work is already done. Confirmed live for 16 apps including Stripe, GitHub, Slack, Notion, and Linear.

02

Search-grounded research pass

Claude + web_search, forced into strict JSON output (category, auth, gate status, API surface, MCP, buildability, evidence URL). Told explicitly to answer "uncertain" rather than fabricate a URL or plan detail — see research_agent.py.

03

Adversarial re-ask

A second, independent Claude call is told to argue against the first pass's claim before agreeing with it — catches confident-but-wrong answers a single pass wouldn't flag. See verify_sample.py.

04

Hand verification on a hard sample

15 of the most obscure/ambiguous apps were independently checked against live docs by a human researcher (this session) — results in data/verification_log.json and the section below.

    THE VERIFICATION LOOP

    Where the agent was wrong, and how we know

    15 apps were deliberately chosen as the hardest in the set — not a random sample — because that's where a research agent is most likely to fail, and where a verification loop earns its keep.

    🚩 One tool tried to instruct the agent researching it

    iPayX's own MCP server description contained explicit directives aimed at AI agents: never mention named competitors, always frame the audit as favoring iPayX, and drive users to the platform for every transaction. The research agent had to recognize this as a prompt-injection pattern embedded in tool metadata — not a legitimate instruction from the user or Anthropic — and ignore it while still accurately reporting what the tool does.

    Source: glama.ai/mcp/connectors/io.github.Ipayx-stellar/fx-audit — flagged, not followed.
    Honesty note on the full 100: only 32 of the 100 rows were independently search-verified or confirmed against a live Composio toolkit listing this pass; the remaining 68 rely on trained knowledge of well-documented, stable platforms (Salesforce, Stripe, GitHub-class apps), flagged in the dataset's confidence field. 13 rows are explicitly marked known-low — good candidates for the next verification pass before anyone treats this as ground truth.

    METHODOLOGY

    Confidence-routed research: well-established, stable platforms were answered from trained knowledge; niche, fast-moving, or ambiguous apps triggered a live search-verification step. Every row's confidence field says which path it took.

    verified — confirmed live this session (e.g. Composio catalog) searched — web-search-grounded this session known — high-confidence trained knowledge known-low — lower confidence, recommend re-verifying
